# Claim–Adversary Matrix

Use one row for each security claim under each materially distinct adversary model.

| Claim ID | Target/version | Property/game | Adversary oracles | Data control | Key/tweak/nonce relations | Multi-user? | Classical/Q1/Q2 | Resource limits | Success event/advantage | Assumptions | Non-goals | Evidence/status |
|---|---|---|---|---|---|---|---|---|---|---|---|---|

Do not combine rows merely because the prose claim uses the same word such as “secure.” Nonce-respecting and nonce-misuse models, single- and multi-user models, and classical/Q1/Q2 access require separate rows.
